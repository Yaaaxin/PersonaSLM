# P1d Instruct readiness — v1

Maintainer: Yaxin ZHENG. Status: NOT EXECUTABLE; no model substitution or inference.

The intended same-family post-trained model is [Qwen/Qwen3.5-2B at revision 965dcc54bc9c0591873df0e9869c056a54d323d1](https://huggingface.co/Qwen/Qwen3.5-2B/blob/965dcc54bc9c0591873df0e9869c056a54d323d1/README.md). Its official card identifies the Base parent and non-thinking default. The pinned configuration, tokenizer metadata and standalone chat template are locally preserved; no Instruct GGUF is present. The official maximum context is not a promise of local CPU capacity; the proposed study context remains 4,096.

The standalone template hash is `0286b273dc0e7dbcc080469bf5b8e57b329c135db0de8a45cb16f80a8b0c4ce6`. Its assistant reasoning guard differs from the embedded tokenizer-config template. This turn rendered all **288 candidate prompts** from the actual standalone bytes using Jinja2 3.1.6 / MarkupSafe 3.0.4 in an isolated local target directory. The proposed mapping uses one user message containing the unchanged Base task body minus its terminal Assistant marker, with enable_thinking=false and no extra system instruction. Fixed dialogue remains quoted task content. This mapping is documented and unfrozen, not a silent change to approved experimental inputs.

For this single-user mapping the two official template variants render identically; a separate assistant-after-user probe demonstrates that they differ on other conversations. The [rendering verification](validation/p1d/scientific_validation_v1/official_template_rendering_verification_v1.json) and [288 rendered candidates](validation/p1d/scientific_validation_v1/instruct_rendered_candidates_v1.json) preserve the exact evidence. Direct Jinja rendering does not prove Transformers or llama.cpp/minja equivalence. EOS metadata identifies im_end, but actual Instruct GGUF tokenization and local stop behavior remain unmeasured. No manually reconstructed template or Base-tokenizer approximation is substituted.

The [bartowski quantization card](https://huggingface.co/bartowski/Qwen_Qwen3.5-2B-GGUF/blob/main/README.md) reports b9222/imatrix quantization and links the upstream model, but the inspected card does not pin the exact source-weight revision required here. A remote GGUF checksum is not local verification. No surveyed third-party artifact was silently selected. Feasible routes are a fully traceable existing conversion, or an independently recorded conversion from the pinned official revision with exact converter, quantizer, source hashes and calibration corpus. Neither route has been completed. Native template equivalence, full vocabulary equivalence, backend compatibility, RAM, latency and native stop behavior remain open. Weight storage is not peak process RAM.

The selected subset is **24 speakers, both cases, all six cells = 288 Instruct requests**, matched to 288 already-counted Base requests. Each family has 12 cases and each date stratum 24. Supported secondary estimands are paired model-configuration differences within a cell or any registered case contrast on these 48 cases, followed by speaker aggregation. No complete 144-speaker model interaction or pure post-training causal contrast is supported. Model weights, quantization, official chat template and possible stop behavior can all differ. The existing model-comparison registry remains unchanged.
